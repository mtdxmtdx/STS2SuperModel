# Public primary reward identity proposal

This module is for the separately declared Rewards-only hybrid hypothetical prior. It does not change v7, native sequential seeds, production eligibility, or the native reward rules. It conditions the ordered first three base primary combat card IDs from complete typed public run evidence, including unpicked options, for arbitrary supported public inventories. All original upgrade draws, potion/gold, appended/extra/rerolled cards, enchantments and late hooks retain their native law. The caller must still require equality of the entire final public packet, including all displayed offers and refreshed observations, before correction and unweighted admission.

## Boundaries and native execution

`NativePublicRewardCondition.Create` reads only `PublicRunEvidence`: observer-owned combat starts count native combat indices, victory closure links the first following same-floor/act/parent reward owner, and that owner's first primary card group supplies `card:card:0..2`. It neither uses `SourceTrace` nor accepts a source seed, graph, hidden pity or private outcome ledger. Refreshed observations are not new random generations. The first three IDs are a necessary event even when LastingCandy appends a fourth card.

The added optional final `LabelRandomScope` callback receives the actual native selection context at two `CardFactory.CreateForReward` overloads, after the existing creation-options hook has run exactly once and before rarity/index draws. Native code computes ordered branch pools and exposes `CardRarityOdds`' actual strict float thresholds. There is no recursive native probe inside a label callback. Native calls still draw, mutate pity, clone, upgrade and apply all reward modifiers.

The public proposal activates only for the normal sequential primary legacy overload. The generic exact finite math also supports the creation-options overload: its uniform branch omits a rarity draw, its selected-ID exclusion and `Distinct` are preserved, and cyclic fallback retains the hidden rolled rarity. These branch families are not substituted for one another. Other event/custom generation remains unaccelerated; malformed/ambiguous required primary evidence or an unexpected native boundary is an explicit unresolved proof failure.

Integration: construct `NativePublicRewardProposal(condition, wasVisited, forceFresh, independentProposalWord)`, pass `BeginCombatReward(context, combatIndex)` and `BeginSelection` into the scope callbacks, then call `ValidateCompletion` and compose `AcceptCorrection` after whole-packet equality. The object exposes its accumulated exact ratio, fixed root envelope and conditioned card count. Replays must reconstruct the same proposal randomness and oracle overrides.

## Exact law and envelope

Let D = 2^53. Native `Rng.NextFloat` casts the 53-bit `NextDouble` to float, including values rounded to 1. Strict rarity comparison boundaries are obtained by binary search over all integer preimages. Index buckets use the exact native double multiplication and integer cast, not ideal 1/N masses. Low unused raw bits remain uniform.

For target A and every hidden rolled rarity r, let R_r be its number of rarity preimages, and I_r(A) the sum of all matching index-bucket sizes in that branch's ordered pool. The local likelihood is Z = sum_r R_r I_r(A) / D². Sampling r proportional to R_r I_r(A), then independent uniform rarity and matching index preimages, gives p/q = Z. The no-rarity branch has a dummy full domain which cancels, giving Z = I(A)/D. Zero enumerated mass is a proved public mismatch. Incomplete/invalid branches are not zero mass.

The correction retains product Z across all three slots of every recorded primary reward. In particular it never substitutes displayed rarity for rolled rarity and never discards changing pity probabilities. Native rare resets and common/uncommon increments remain latent and affect later rewards. Full-offer equality supplies the remaining unconditioned native factors, each with ratio 1.

The root certificate conservatively enumerates four ordered native catalog configurations for the public character: character; character then colorless; all character pools; all character pools then colorless. The canonical all-character order is Ironclad, Silent, Regent, Necrobinder, Defect. Pool enumeration uses actual native `GetUnlockedCards(AllUnlocked, false)` and preserves its ordering. The four families have common/uncommon/rare counts 20/35/25, 20/67/46, 100/175/125 and 100/207/146 before exclusions.

These configurations form a superset of every public-inventory-compatible pool. Only DingyRug and PrismaticGem alter primary creation pools in this pin, their union operations are idempotent, and both orders yield the same families. We intentionally do not prune by observed ownership or current active state: ToyBox may melt a wax relic after combat and before generation. That conservative looseness is root-constant and avoids treating sampled live inventory as an envelope proof.

For slot j, enumerate every possible canonical-reference exclusion consistent with earlier target IDs, retaining duplicate entries and every matching reference choice. Set b_j to the maximum exact sum of matching index-bucket masses across every remaining catalog and rolled-rarity pool. Then each local Z_j <= b_j because rarity masses sum to 1, regardless of hidden pity, so B = product_j b_j bounds product_j Z_j. Runtime ordered remaining pools and branch memberships must match the certificate. Acceptance is exact rational Bernoulli (product Z)/B; no ratio-one shortcut is used. This proof bounds a compatible-pool superset; it is not a claim that B is the smallest possible public-inventory bound.

## Freshness and failure mass

Native sequential `RewardsSet.GenerateFor` populates the primary card before extra rewards. Its audited legacy slot has exactly one rarity, one index and one upgrade draw on persistent `player.PlayerRng.Rewards`; creation modifiers make no random draw. There is no clone, restore or lookahead on this path. Mutable card cloning copies card state, not the player's stream. LastingCandy and PrayerWheel consume later draws. The native modifier inventory was searched exhaustively at this pin.

Each slot verifies the RNG is the owned Rewards object with explicit `rewards_lineage` provenance, both rarity/index addresses are unvisited, and the oracle accepts fresh forcing. At slot exit it verifies both cells were visited and the raw cursor advanced by exactly three with unchanged lineage. Earlier ordinary consumption may advance the cursor; it cannot weaken the fresh-cell requirement. Full-state, already-read cells, altered pools, missing callbacks, added/skipped/restored draws and invalid envelope are unresolved errors, never rejection/drop/resampling. The oracle must also enforce conflicting override rejection. These assertions supplement the pinned call-path proof; net cursor advancement alone is not a general arbitrary-code no-lookahead theorem.

## Verified modifier scope

Native source audit: MoltenEgg/FrozenEgg/ToxicEgg, SilverCrucible and LavaLamp upgrade same-ID clones in place. Glitter/SilkenTress/FresnelLens and WingCharm enchant same-ID clones in place; WingCharm uses Niche, still full-state law. SilverCrucible and SilkenTress update counters after modification. LastingCandy appends after the ordered base prefix. `ModifyRewards` receives only the extras list after primary population. These rules remain native and are not reimplemented by this proposal.

Focused tests cover 2/3-bit exact hidden-rarity mixtures (posterior 3/5 versus 2/5), a later outcome distinguishing reset/increment paths (5/8 versus 3/8), duplicate matching indices, actual creation-options fallback and native pity mutation, native float boundary neighbors including rounded 1, explicit alias/full-state failure, and actual primary native generation with ordinary, Rug, Gem, both, all eggs/WingCharm, LastingCandy and PrayerWheel inventories. A real complete two-combat public capture verifies mapping and refreshed-offer deduplication. Full production acceptance/throughput, full sampler admission and broad M3–M6 completion are not established by these focused fixtures.
