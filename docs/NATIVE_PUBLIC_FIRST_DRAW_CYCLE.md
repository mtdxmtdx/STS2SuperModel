# Public first draw cycle certificate

`nosl.public-first-draw-cycle.v4` extends the explicit public-combat startup certificate to the observed first draw cycle. It changes only proposal acceleration under the declared independent primitive tape law. Legacy `NativeInitialShuffleCondition.TryCreate`, the v2 public startup entry point, the run-seed prior, public packet schemas, and final equality checks keep their existing behavior.

## Why draw facts alone are insufficient

`PublicKnowledge.CardMoved` intentionally omits arbitrary pile moves. For example, `ThinkingAhead.OnPlay` draws two cards and then returns a selected card to the top without publishing a move fact. `PotionUseFinished` publishes only after potion effects. Consequently neither a run of `CardDrawn` facts nor absence of `Shuffled` proves that later draws are positions of the original shuffle.

The certificate starts at the first stable public combat decision after certified startup. It walks the original typed owner history, linking every action to its immediately preceding public decision. Before crossing an action, it proves that the action's entire continuation can only remove cards from the remaining initial pile through ordinary `CardPileCmd.Draw`. Unknown transitions stop the extension permanently; they do not erase the already certified startup prefix or exclude content from the underlying prior.

## Source closure

The proof is pinned to the vendored simulator sources, particularly `CardModel`, `CardCmd`, `CardPileCmd`, `CombatEngine`, `Hook`, and the complete concrete implementations named below. It does not inspect an original native object graph, original hidden order, seed, source trace, or audit payload.

- Startup retains the existing reflection check of all entry cards, relics, and potions against `AbstractModel` hooks and the reviewed startup monster closure. Reviewed relic hooks only alter counts, energy, or counters across subsequent turns as well
- Played cards are the exact sealed `StrikeSilent`, `DefendSilent`, `Neutralize`, `Survivor`, `Backflip`, `Deflect`, `Mirage`, `NeowsFury`, `Strangle`, `Finisher`, `SuckerPunch`, and `Slimed` types. Their effects and upgrade branches only change damage, block, Weak/Strangle, current-hand discard, discard-to-hand retrieval, or ordinary draw. The generic `GeneratedCardModel` base is not admitted; only the Strike/Defend specs and their absent generated-power mapping are reviewed
- Survivor is rejected before execution if any current hand card has permanent or temporary Sly, including automatic single-candidate selection. `CardCmd.Discard` can otherwise autoplay it without another public action. Pending choices must be the same admitted Survivor continuation
- Potions are checked before their action, using the selected public potion slot. Only exact Fire, Block, Energy, Strength, and Swift potion implementations are admitted
- A turn-ending action requires every current hand card to inherit `CardModel`'s false `HasTurnEndInHandEffect` and no-op `OnTurnEndInHand`. Ordinary flush and Ethereal exhaust affect the current hand only
- Enemy turns admit all move callbacks and transitions of exact `CorpseSlug`, `SludgeSpinner`, `Toadpole`, `TwigSlimeS`, `TwigSlimeM`, `LeafSlimeS`, and `LeafSlimeM`; these attack, apply reviewed powers, change AI state, or generate the explicitly reviewed plain Slimed to Discard. Public numeric intents alone are never treated as evidence of a move implementation
- Active powers admit exact Weak, Frail, Strength, Ravenous, Strangle, and Thorns implementations, including application/removal behavior. Ravenous changes CorpseSlug AI and applies Strength on death; it never changes card piles
- Orbs, pets, afflictions, changed relic membership, and changed monster identities disable further extension. Only the exact Sharp enchantment is admitted

The explicit v3 startup entry points additionally admit `LavaRock.ModifyRewards` and Sharp. `CombatRoom` dispatches reward modification only during post-victory settlement, never during startup or an unfinished draw cycle. Sharp's only custom effect is additive attack damage; inherited draw/play/shuffle-order callbacks are no-ops. These exceptions do not alter the legacy startup or HP entry points.

At every stable snapshot, the unordered public draw multiset and count must equal entry cards minus the certified draws; known draw positions and unidentified cards are absent under this closure. These checks detect contradictions but do not replace the transition proof. Gaps, unreviewed powers/effects or generation, pre-settlement, or the first shuffle stop the certificate. The last ordinary draw before a shuffle remains valid, including a prefix equal to the complete entry deck. Later reshuffle draws are never folded into that permutation.

## V2 card continuation extension

V2 adds four measured card-action blockers without changing the native rules or shuffle probability machinery. Historical v1 reports keep their original certificate identity and stop reasons. The optional witnessed-reshuffle condition reuses the same versioned transition closure; its pool witness and exact correction law are unchanged.

- `NeowsFury` deals ordinary attack damage, then takes up to two discard cards (three upgraded), additionally bounded by available hand capacity. Each move uses `CardPileCmd.Add(card, Hand)` with the default Bottom position. This path has no random insertion, `Draw`, draw callback, card-entry callback, discard callback, or Sly autoplay. Its native result is Exhaust. This certifies the pinned simulator's existing first-eligible-discard behavior, including its documented selection-UI deviation; it does not change that behavior
- `Strangle` deals attack damage and applies `StranglePower`, with only numeric changes when upgraded. The power's `BeforeCardPlayed` stores the current amount by physical card; `AfterCardPlayed` removes that snapshot and deals direct unblockable, unpowered damage. Its side-end hook removes itself when its owner participates. It inherits no-op application/removal callbacks. Clone/description methods manipulate only private snapshot bookkeeping or validate it; they never mutate live piles
- `Finisher` reads the completed-Attack counter for its hit count; upgrading changes only damage per hit. Neither counter access nor attack resolution draws, creates, transforms, or moves a card
- `SuckerPunch` deals attack damage and applies the already reviewed Weak power. Both upgraded branches change only numeric damage and duration

The shared `DamageCmd`/`CreatureCmd`, generic card play/result paths, and `PowerCmd` application/stack/removal callbacks remain inside the existing listener closure. Strangle's direct damage can dispatch those same death hooks; Ravenous only affects surviving CorpseSlug AI and Strength. The new members do not request extra turns, reroll monster moves, replace Sludge/Leaf intents, generate cards, or create a new listener outside the enumerated powers. Previously admitted entry relics only alter their reviewed counts/energy/counters. Entry cards retain the initial hook reflection guard, and Sharp remains the sole admitted enchantment.

NeowsFury's silent discard-to-hand movement intentionally requires no hand/discard ledger: it leaves the current draw pile unchanged, while a later reshuffle's public post-shuffle witness fixes that later pool. The existing Sly guard still runs before any later Survivor discard. Generation, unfamiliar cards/powers, and the existing unreviewed enemy-turn families still stop certification; Slimed generation is not admitted by this change.

## V4 measured weak-slime continuation

V4 crosses the measured first-turn draw blockers in retained roots 11006 and 11007. The complete sealed native types are the proof: TwigSlimeS only attacks; TwigSlimeM attacks or generates one Slimed; LeafSlimeS attacks or generates one Slimed; LeafSlimeM alternates attack and generation of two Slimed. Each generating move constructs an unupgraded canonical Slimed, assigns the target player, and calls `CardPileCmd.Generate(..., Discard, creator: null)` with the default Bottom position. There are no summons, power additions, extra turns, or intent replacements. Ordinary graph branch selection remains native and does not execute any additional move callback.

`PublicKnowledge.CardEnteredCombat` publishes a full card for visible piles but omits the destination. A `CardGenerated` fact alone is therefore insufficient. The certificate only admits plain Slimed during an already certified end-turn action, with a remaining upper bound from the live source-reviewed StatusCard-intent slimes at that action's public snapshot. Public StatusCard intents omit their count; the exact sealed implementations supply one or two. The window closes at PlayerTurnEnded, a draw, a shuffle, or the next snapshot. Hidden generation, any other card/metadata, excess generation, a non-generating intent, or another action stops the closure before the event. The bound need not be exhausted: combat ending or death may suppress moves, and complete native public equality still checks every actual event.

`EnterCombatInternal` first inserts into Discard and dispatches the complete entry-hook snapshot, then publishes the visible generation fact. `Generate` subsequently dispatches both generation hook surfaces. All admitted entry cards, relics and potions remain covered by startup reflection; the explicitly reviewed powers and monsters have no generation/entry effects, and the newly created Slimed inherits all these no-op hooks. The generated card becomes another safe listener. End-turn flush uses plain Add and does not invoke Sly discard autoplay; Survivor's separate Sly guard remains mandatory.

Slimed's complete OnPlay is ordinary `Draw(1, fromHandDraw: false)`, followed by its inherited Exhaust result. Its own entry, draw, generation, exhaust and turn-end hooks are no-ops. The generic play wrapper, cost/hand-capacity gates, possible reshuffle after Draw empties, draw hooks, and exhaust callbacks stay inside the same listener closure. No cross-class play or additional power becomes eligible.

Known inventory is now the public entry multiset plus only these accepted generated-card facts. It is an upper bound, since cards may be held or exhausted. A later reshuffle still requires its joint post-shuffle snapshot to fix the exact pool; neither this upper bound nor a sampled native pool chooses the root envelope. Generated cards have no DeckVersion, so the exact reshuffle boundary allows only owned plain Slimed without one. Distinct physical references, actual draw/discard union, the exact native marker, fixed pool equality, and all forcing/counter/completion checks remain mandatory. Initial shuffle ownership rules are unchanged.

## Sampling and correction

The constraint uses card type IDs deliberately. Different upgrades and enchantments with the same ID remain distinct physical indices in `ConditionalShuffleProposal`; the complete entry anchor and final native public equality retain their full metadata. No uniform choice over coarse card identities substitutes for a physical permutation.

For public prefix IDs `p[0..k)`, the uniform physical-permutation event probability is the product of the remaining multiplicity of `p[i]` divided by `n-i`. Extending the prefix changes this factor and nothing else in the proposal math. The existing proposal samples each compatible physical permutation uniformly, inverts its native Fisher–Yates path, and samples full raw words inside the exact native floating-point buckets. Native-to-proposal ratios and root-constant rejection envelopes retain all bucket factors. Every completed combat's correction remains in the product. State alias checks, already visited cells, raw-word consumption, and full evidence equality remain mandatory.

The per-combat audit exposes certificate version, initial and extended draw counts, last certified event ordinal, and stop reason. This is a bounded computational improvement, not production admission, finite-seed posterior certification, or evidence of an independent posterior sample.
