# Public opening encounter proposal

`NativePublicOpeningEncounterCondition` is an optional acceleration for the first
normal encounter in a fresh Silent A10 native state-tape or Rewards-hybrid run.
It reads only detached typed public evidence. It does not require the narrow
second-combat retained-Neow/reward certificate used by `NativeFirstEncounterCondition`.
Unsupported evidence leaves the declared native prior and all roots eligible for
ordinary replay. This is not an encounter coverage gate.

## Eligibility and native source proof

The recorded prefix must start with Silent A10, contain no gap before the first
turn-one roster, and contain a complete first combat owner at act zero/floor two
with no event parent. Its one preceding map owner must record the first move
from the row-zero Ancient to a row-one Monster and complete that choice. A forced
event combat, an earlier combat, a missing first map choice, an unknown room, or
an unobserved first roster is not silently interpreted as normal slot zero.
Gaps after the opening do not erase the already observed certificate.

The native `StandardActMap` fixes row one as unmodifiable Monster. `RunDriver`
processes Neow first and then the selected map point. `RoomFactory` resolves a
Monster directly and pulls the next stored normal encounter. `RunState` generated
that sequence before Neow, and `ActDefinition.PickWithoutRepeating` starts its
weak GrabBag with four equally weighted entries. No previous normal encounter
was pulled at the certified opening. The existing pool guard pins order, tags,
weak count and shape for Overgrowth and Underdocks.

The observed roster is the consecutive typed `IntentPublished` group immediately
after the first `PlayerTurnStarted(1)`, not the current root's enemy list. All eight
weak entries have disjoint full roster support. This support is generated by the
native factories, rather than a hand-written roster mapping. The only randomized
factory paths are exhaustively enumerated using their reviewed native index
kernels: Overgrowth weak slimes draw `NextItem(2), NextItem(1), NextItem(2)`;
Underdocks corpse slugs draw `NextInt(3)` for their distinct initial moves. The
other six factories draw nothing. Enumeration checks complete draw consumption
and native slot shape. Startup hooks do not turn one weak family into another;
removals cannot make another weak batch equal a certified full roster.

Only the encounter identity is proposed. The slime formation, slug initial moves,
monster HP, entire first combat, later encounters and all other native behavior
remain in the native replay law. The whole original public prefix still needs to
match. Selecting the slime family does not claim the observed particular formation
has been conditioned.

## Finite law and correction

Let Q = 2^53. The first four-entry GrabBag draw uses the native high-53-bit
`NextDouble` and strict cumulative comparisons. Its four complete buckets agree
with the source-pinned `ConditionalShuffleProposal.Factor(4, index)` integer
conversion and each has Q/4 values. The proposal samples uniformly within the
chosen bucket and independently samples every discarded low bit. Therefore each
compatible full word has native/proposal ratio (Q/4)/Q = 1/4. This is the
root-constant envelope, so its rejection correction accepts without a random
word. This claim concerns the declared ideal full-state oracle law, not a finite
SHA256-key posterior or a common-run-seed posterior.

The target act is a public nonmatch when native act selection differs. This
helper does not replace the native act constructor or independently resample an
act while holding an incompatible initial map history. A joint fresh initial
prefix proposal may use `TargetActType` alongside its existing map predicate.

## Integration contract

The helper is detached so callers can integrate alongside other prefix changes:

1. Create the optional condition from the public root and declared prior. Keep
   ordinary fallback when `TryCreate` returns false.
2. Construct `NativePublicOpeningEncounterProposal(condition, nextProposalWord,
   ForcePrefixWords)` using an independent proposal RNG domain, for example
   `nosl-public-opening-encounter-v1`. Pass the existing tape method with signature
   `(IReadOnlyList<ulong>, Rng, string) -> IDisposable`.
3. Attach the same owned native run in the tape's normal attachment callback.
   At the native first-act normal-generation hook, call `BeginGeneration`.
4. Keep `ForcePrefixWords`'s primitive pre-state, unseen-cell, override-consistency,
   whole-word-consumption and stream guards. An alias is an engine/certificate
   error; it cannot become a clean public nonmatch or a forced overwrite.
   The adapter and its world are single use after any exception. The delegated
   force scope preserves the original callback error by suppressing a secondary
   disposal error; therefore completion is not a recovery guarantee after an
   error was caught. Propagate the original error and discard the failed world.
5. Validate completion, apply correction, preserve the condition and proposal
   coordinates through owned replay copies, and still compare all public evidence.
6. Do not concurrently run the old two-word slot-one condition over the same first
   cells. Prefer this first-opening condition when available, or implement a
   separately proved joint slot-zero/slot-one kernel. Multiplying two overlapping
   proposal ratios is invalid.

Tests connect the detached helper to the actual production tape guard through
reflection, without changing `NativeLabelTape` merely to wire the fixture. They
exercise all eight native weak selections, independent native replay, exact owned
replay, full finite buckets and low bits, native bag endpoints, unavailable
certificates, retained earlier evidence, state/stream aliases and completion.
They do not establish full sampler acceptance rates or end-to-end M3–M6 completion.

An independent read-only review of commit `09982de` found no blocking issue in
the slot-zero certificate, factory support, finite law or delegated tape guards.
It confirmed the abort-on-error integration requirement above and the remaining
production-integration and acceptance-rate limits.
