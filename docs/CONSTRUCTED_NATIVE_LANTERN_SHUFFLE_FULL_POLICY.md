# Lantern initial-shuffle action evidence

The typed Lantern action bridge accepts the explicitly enabled
`nosl-constructed-native-event-tape-shuffle-v2-public-evidence-v2` implementation,
paired with `owned-constructed-native-event-tape-shuffle-v2-public-evidence-v2`.
It requires the existing declared TheLanternKey owner prior. There is no new
prior, source-generation identity, natural-start claim or admission subtype.

The implementation/profile pair is fixed before native execution. V2 requires
`enableConditioning:true`, including when a particular startup is uncertified
and uses ordinary rejection. Historical rejection-v1 reports remain valid with
their exact original pair and zero conditioning counters. Older v1 producers
ignored the enabled flag for event sources; their retained enabled=true report
is preserved. The new producer's disabled reference path also uses rejection-v1.

The helper validates the exact existing event parent, combat child, floor,
offers and KEEP_THE_KEY → FIGHT choices. A claimed eligible v2 startup additionally
requires the unique initial missing-run-start gap, first local revision zero,
the slot-zero MysteriousKnight at native HP/maxHP108 and block6, exact native
Strength/Plating6 facts and the Attack17 RAM intent. These facts come from the
first public combat decision and its startup history, even when a later root is
selected. It never changes the public packet or conditions on actual source RNG.

Every event-v2 proposal must retain zero conditioned HP, at most one initial
shuffle and no more conditioned tape words than the published entry deck's
Fisher–Yates permutation requires. Completed conditioned proposals must retain
all those words. Acceptance, full-packet mismatch and density rejection all
require a completed shuffle when the source claims eligibility. Error,
cancellation and early constraint failures may retain partial counts. An
uncertified source retains zero conditioned counters under v2; its absence,
failure and exhaustion records remain visible.

The later-draw exclusion is a property of the reviewed native constructor,
which passes no draw-prefix extension or reshuffle plan. The raw API does not
export a separate draw-prefix certificate, so Python does not invent one. It
binds the exact native source dependency bytes and raw build receipt. The source
fingerprint already includes the owner, initial-shuffle and combat-prefix
condition/proposal files; it now also explicitly includes
`ConditionalShuffleProposal.cs` and `NativeLabelTape.cs` for density correction
and conditioned-word consumption. Public startup checks complement those native
proofs; they do not replace the native hook/listener audit.

All raw values, masks, outcomes, execution counters and attempts remain embedded
exactly. Candidate cost is recomputed using the existing pure math. Unknown
potion or SpecialCardReward opportunity values remain unresolved and masked.
The normalized subtype remains engineering-only with `native_run:false`, no
producer receipt, no ranking/plan labels and all training/admission gates closed.
Historical artifacts are immutable; newly normalized rows bind the current
source closure separately.

report for integration tests. Missing reports cause an explicit skip and never
trigger native generation. Integration and guarded forward claims require the
separate verification artifact for the actual report.
