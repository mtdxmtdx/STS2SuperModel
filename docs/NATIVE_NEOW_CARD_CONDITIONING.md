# Public initial Neow card conditioning

This is an opt-in proposal under `nosl.native-rewards-state-tape-prior.v1`, not a change to the prior or to sequential gameplay. It accepts only a complete typed public run prefix whose initial Neow opening is already certified by `NativeNeowCondition`. No source seed, source recipe, source graph, or private outcome trace is read.

The supported sources are ArcaneScroll, ScrollBoxes and Kaleidoscope for the native fresh solo Silent A10 startup. The public starting inventory must contain RingOfTheSnake alone. Their actual native generation must still run in the owned initial Neow room, on floor one, with exactly the starter and selected relic. This closes the creation-modifier inventory: RingOfTheSnake and these pickup relics do not change card creation pools. A pool or overload change fails closed.

Subsequent extensions also cover [LostCoffer](NATIVE_NEOW_LOST_COFFER.md) and
[NewLeaf/LeadPaperweight](PUBLIC_NEOW_TRANSFORM_COLORLESS.md). The latter preserve
NewLeaf's one Niche transformation word and LeadPaperweight's colorless rarity
fallback arms; they do not reuse the three-arm-present certificate below.

* ArcaneScroll: remove the complete public starting deck multiset from the initial event's public settled deck. The one remaining identity is its grant. Native `CardFactory.CreateForReward` uses the uniform rare-only pool and NoUpgradeRoll, so it consumes one Rewards word.
* ScrollBoxes: read both complete three-card bundles from the initial child choice owner. The unselected bundle contributes all three identity constraints. Native `GenerateRandomBundles` consumes six Rewards words for the certified Silent path, with common/common/uncommon order in each bundle and the native cross-bundle ID exclusions. The Defect Claw branch is not certified.
* Kaleidoscope: read all three candidates in each of the initial primary and extra offers, before any selection or refresh. Each identity must belong to exactly one of the four other character pools. Each offer requires three distinct pools; that prefix fixes the complete four-pool permutation. The proposal conditions both native Niche shuffles and all six native base-rarity/index draws. The six upgrade words remain ordinary Rewards oracle draws. All three rarity arms must exist in each certified catalog pool; unsupported fallback shapes fail closed.

The label-only ScrollBoxes hook snapshots its actual common/uncommon pools after the existing creation modifiers, immediately before the unchanged native loop. It does not replay modifiers, select a card, add a draw, or change the ordinary path. The proposal verifies these pools against the fixed startup catalog before forcing any cells.

For every index draw, use the exact finite preimage of native double-to-index conversion. If a target occupies multiple positions, sum their bucket masses. `NativeRewardIdentityMath` samples uniformly within the target preimage, including all low raw-word bits. For Kaleidoscope, the helper also counts the exact native float-rarity preimages, retaining each latent rolled-rarity arm. Native `RollWithBaseOdds` depends only on the public A10 ascension here, not the hidden pity value; a catalog odds object calls the native threshold getter without any random draw or source run. Each pool has all three rarity arms, and the runtime callback checks the same thresholds, candidates, source, flags and unchanged-future-odds contract. The Niche factor is the exact raw-word mass of each uniquely determined four-pool permutation, not the idealized 1/24.

The likelihood factor Z is the product of the required permutation and identity masses. All pool shapes, base thresholds and exclusions are fixed by this public root, so its envelope B equals Z and correction accepts with probability one. Conditioning only the selected bundle would use a different Z and would not condition the recorded evidence.

Every forced address is checked for freshness in the Rewards origin/seed/raw-cursor partition before any write. Scope completion checks that the native generator visited every planned cell and advanced by exactly the certified number of raw words. Kaleidoscope delegates state-partition forcing to the owning tape, which rejects previously visited or conflicting full-state cells; its two shuffle boundaries and six selections must interleave in the native order. Replays use the same deterministic proposal seed and retained oracle overrides; previously visited or conflicting cells cannot be overwritten. Unrequired native draws retain their original oracle law. The full existing public-equality check remains responsible for all other observations.

Validation includes finite raw-word bucket/permutation/rarity enumeration, omission of the unselected bundle or second offer, alias rejection before Rewards writes, actual native Neow event generation in independent hypothetical runs for all three rarity arms, exact opening evidence, untouched upgrade cells and pity odds, and replay/continuation through `NativeRunWorld`. The module test helper substitutes Niche words directly; full-state alias and conflicting-override rejection must additionally be exercised through the owning `NativeLabelTape.ForceWords` integration. It makes no claim about unimplemented startup card sources or production acceptance rates.

## Integration

Create with `NativeNeowCardCondition.TryCreate(root, prior, out condition, out reason)`. For each owned hypothetical replay, construct `NativeNeowCardProposal(condition, rewardsOracle.WasVisited, rewardsOracle.ForceFresh, proposalRng.NextUnsignedLong, ForceWords)` using a separate deterministic proposal stream. Attach its native run, route `BeginSelection` alongside primary reward selection, pass `BeginScrollBoxes` to the new trailing optional label-scope callback, and route `BeginShuffle` before the general combat-shuffle handler. The final constructor parameter is optional for ArcaneScroll/ScrollBoxes and required for Kaleidoscope: it must be the owning tape's fresh-cell full-state forcing function. Compose `ValidateCompletion` and `AcceptCorrection`; recreate the proposal on an exact replay. `ConditionedCardCount`, `ConditionedPoolShuffleCount`, `NativeToProposalRatio`, and `Envelope` expose diagnostics.
