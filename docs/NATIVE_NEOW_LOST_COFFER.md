# Public LostCoffer proposal

The initial Neow LostCoffer source displays three ordered card options and one
potion before the public outside-combat policy chooses. The condition reads
that first complete reward owner, including unpicked cards and the displayed
potion. The selected deck alone is insufficient. Missing offers disable the
proposal; the remaining full public history is still checked normally.

The authoritative native path is `LostCoffer.AfterObtained`, the creation-options
`CardFactory.CreateForReward` overload, and `PotionReward.Populate`. For the
owned initial Silent inventory, the card pool is fixed. Each slot uses base
regular-encounter rarity odds without changing future rarity state, removes
previously selected ModelIds, and consumes a separate upgrade word. Native
callbacks validate the exact pool, flags, source, slot and thresholds. The
potion follows the three cards on the same Rewards-origin stream and uses the
unchanged character-plus-shared pool and native rarity/index arithmetic.

For public identities c0,c1,c2,p, let zi be the exact raw-word mass of ci in the
pool after earlier public identities have been excluded, and zp the exact potion
mass. All are fixed by this public root and the native catalog. The proposal
samples the corresponding conditional rarity/index words. It retains all three
ordinary upgrade words and every later native word. Its native/proposal factor
and common root envelope are the same product z0*z1*z2*zp, so their correction
ratio is one. A later observed upgrade or other public fact remains in final
replay equality. No rarity, identity, or resource value is invented.

Every forced Rewards cell must be fresh. Origin/partition/law, owned run and
player, Neow timing, and draw advances are checked. Completion requires all three
cards and the potion, with a sticky failure flag. A foreign, repeated, skipped,
aliased or reordered callback cannot produce an accepted proposal. The outer
Neow potion callback is temporarily superseded by existing native combat-reward
scopes; it is inactive outside the initial Neow event.

Native fixtures cover common, uncommon and rare source words, exact complete
Neow public evidence, unchanged upgrade words, replay, missing unpicked offers,
and alias rejection before any forced writes. A finite product-world check
counts native rarity/index words with ModelId exclusions and retains an
additional predicate on an unconditioned upgrade word. These tests establish
this component's law and lifecycle. Broad independent posterior throughput is a
separate, versioned diagnostic.
